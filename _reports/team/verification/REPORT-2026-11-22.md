## 4) اقتراح دورة العمل التلقائية — «Evidence-First Loop»

### المبدأ
> لا يوجد `COMPLETED` إلا بعد دليل قابل للتشغيل: **اختبار + لقطة شاشة + Commit/ملف**.
> الوكيل ينتج، وHermes يتحقق، وMaxP يتحدث بعد التحقق فقط.

### المراحل
1. **Ingest (كل 30 دقيقة)**
   - سحب 604 مهمة من `/api/v1/external/tasks`.
   - Snapshot + diff: جديدة / تغيّرت / تأخرت.
2. **Triage (Hermes)**
   - تصنيف: تصميم / كود / مراجعة / تشغيل / تحقيق.
   - استخراج قيود «ممنوع تلمس» و«ممنوع كود قبل موافقة».
   - كشف التبعيات والمهام المحجوبة.
3. **Plan (كل صباح 09:00)**
   - ترتيب حسب: Priority + التأخر + التبعيات + حمل الفريق.
   - اختيار 20 مهمة: 5 agy → 5 dsh → 5 opencode → 5 zcode.
4. **Execute (متوازي بحدود)**
   - agy: تصميم/تحليل (لا كود).
   - dsh: كود + اختبارات.
   - opencode: مراجعة QA وأدلة file:line.
   - zcode: **موقوف** حتى يشتغل الموديل.
   - Repo lock + worktree منفصل لكل وكيل؛ ممنوع commit/push بدون موافقة.
5. **Verify (Hermes — مسار مستقل)**
   - نشر/تشغيل على **مختبر هيرميس** فقط.
   - Browser automation: تسجيل دخول، تنفيذ السيناريو، لقطة قبل/بعد.
   - API assertions + pytest.
   - حزمة دليل: `{screenshot, testOutput, commitOrPath, pageUrl, notTestedScope}`.
6. **Gate**
   - PASS → `PATCH /status` إلى `IN_REVIEW` + evidence + progress واقعي.
   - FAIL → إرجاع للوكيل بفجوة محددة (لا نرفع الحالة).
   - BLOCKED → تعيين مالك + سبب + تاريخ.
7. **Report**
   - Digest 09:00 و17:00: ما تم، ما فشل، ما هو محجوب، أعلى 5 مخاطر.
   - تقرير أسبوعي بالاتجاهات.

### الجدولة المقترحة (Cron)
| الوقت | المهمة |
|---|---|
| 09:00 | Plan + dispatch الدفعة الأولى |
| 13:00 | فحص تقدم + إعادة توزيع المحجوب |
| 17:00 | Verify + digest مسائي |
| كل 30 دقيقة | Ingest/diff فقط (بدون تشغيل وكلاء) |

### الضوابط
- لا أسرار في الريبو — فقط `~/.hermes/secrets/`.
- لا كتابة على بيانات الإنتاج؛ الاختبار على `مختبر هيرميس`.
- سقف تزامن: 2 وكلاء كتابة كحد أقصى.
- TTL lock 120 دقيقة + تنظيف تلقائي.
- كل تغيير حالة له `evidence` و`agentInfo` و`notTestedScope`.

## 8) دورة `eea5c862` — dsh انتهت مهلته، والإصلاح تم يدويًا

- **dsh:** 600 ثانية ثم TIMEOUT. قضى الوقت في البحث عن وصول لقاعدة الإنتاج، ولم يعدّل كودًا. لا يوجد deploy إنتاجي triggered (آخر deploy 22:02Z قبل بدء dsh 22:18Z).
- **السبب الجذري:** `scripts/ensure_trgm_indexes.sql` صحيح، لكن `scripts/deploy-remote.sh` كان يشغّله فقط داخل `NEED_DB_PUSH=true`؛ أي الفهارس لا تُطبّق عند نشر كود البحث وحده.
- **الإصلاح:** نقل بلوك الفهارس خارج شرط `NEED_DB_PUSH` ليعمل في كل deploy. السكربت idempotent (`CREATE INDEX CONCURRENTLY IF NOT EXISTS`) ويغطي `customers(firstName,lastName,phone)` + `conversations(lastMessagePreview)` + `messages(content)`.
- **التحقق:** `bash -n scripts/deploy-remote.sh` → OK؛ أسماء الجداول مؤكدة من Prisma.
- **غير متحقق:** التطبيق والقياس على production DB (لا وصول DB/SSH). المطلوب <3s لم يُقس.
- **MaxP:** `eea5c862` → `IN_REVIEW` 80% مع `notTestedScope` صريح.
- **deploy النهائي:** commit `31ab3f446` · run `45080504713` نجح. اللوج يثبت مسح الفهرس غير الصالح ثم **5/5 CREATE INDEX**؛ `idx_messages_content_trgm` اتبنى في **~14m11s** بدون timeout أو خطأ.
