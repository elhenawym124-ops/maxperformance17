## ٣. نقاط الضعف (سلوك صحيح لكن يحتاج تحسين تجربة)

| # | الملاحظة | التقييم |
|---|---|---|
| W1 | شحن محفظة ولي الأمر **لا يُضاف فورًا** — ينتظر موافقة الإدارة | مقصود ماليًا، لكن غير موضّح في البوابة |
| W2 | شراء باقة برصيد صفر يرجع «الرصيد غير كافٍ» (400) | صحيح، لكن ينقص CTA «اشحن المحفظة» |
| W3 | حجز حصة يتطلب اشتراكًا نشطًا — وإلا 404 | رسالة يجب أن تفرّق بين «لا اشتراك» و«انتهى الرصيد» |
| W4 | الحصة تتطلب مدرسًا معيّنًا (400) | صحيح، لكن لا يوجد اقتراح تلقائي من جدول المدرس |
| W5 | تعارض المواعيد يفحص حصص المدرس فقط، **لا يفحص توفر المدرس (slots)** | ثغرة منطقية: يمكن حجز حصة خارج ساعات التوفر |
| W6 | أكواد الطلاب `STU-1001+count` قابلة للتكرار عند الحذف | يجب استخدام تسلسل ثابت أو Unique |
| W7 | تسجيل نفس الرقم في يوم تجربة يعيد استخدام نفس الـ Customer | سلوك مقصود، لكن لا يوضّح للمستخدم «مسجل مسبقًا» |
| W8 | لا يوجد مسار استرداد/إلغاء اشتراك (Refund) متحقَّق | ماليًا مهم قبل التشغيل الحقيقي |
| W9 | لا تُحتسب الحصص الملغاة في تقارير المدرس/المالية تلقائيًا | يحتاج تأكيد قاعدة العمل |
